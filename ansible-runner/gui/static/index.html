Install Parameters

Extra provisioning steps, each optional and independently toggled.

Leave the key blank to use the one stored in vault. Unchecking this box entirely skips Tailscale for this run, even if a key is stored.

Already-installed distros are skipped. Enabling the underlying Windows feature can require a reboot to finish; if not allowed, the run warns and you can re-run later. WSL distros are registered per-user - leave the field above blank to install for this run's own account (the WinRM user, a pure automation account not used interactively), or list specific Windows usernames (comma-separated) to install ONLY for them instead, via a logon task each that runs at their next login, no password needed. The exact manual command is always shown in the run log too, for anyone else not listed.

Runs Win11Debloat with its standard recommended settings (-RunDefaults -Silent): removes the default list of bloatware/preinstalled apps and applies its default privacy/UI tweaks, unattended. Downloads and runs the latest script straight from debloat.raphi.re on the target PC - no extra options here, just the maintainers' own defaults.

Installs every available RSAT (Remote Server Administration Tools) capability - AD DS, DNS, DHCP, Group Policy, Hyper-V, and the rest - via Windows's own Add-WindowsCapability, not Chocolatey. No per-tool picker; this is all of them. Each missing capability downloads from Windows Update, so this can take a while on a fresh machine.

Also applies anything selected on the Software tab.

CIS Benchmark Hardening

Applies an ansible-lockdown CIS role to the selected host(s).

This changes real security settings on the selected host(s) - password/lockout policy, audit policy, services, network protocols, and more. Some controls can affect remote management itself (the same WinRM access this tool depends on) or break older software. Uses ansible-lockdown's CIS roles - read the relevant role's own docs first, and test on a non-critical PC before applying for real.
